# DM-001: FileUploader のチャンクアップロード方式

## ステータス

採用済み (v1 から継続)

## コンテキスト

GPT-SoVITS のモデルファイル (数百MB〜数GB) をブラウザからアップロードする必要がある。

## 方式

3段階のチャンクアップロード方式を採用している。

1. **`GET /api/uploader/info`** — アップロード可能なファイル種別の情報を取得
2. **`POST /api/uploader/upload_file_chunk`** — ファイルをチャンク分割して順次アップロード (multipart/form-data)
3. **`POST /api/uploader/concat_uploaded_file_chunk`** — アップロード済みチャンクを結合して最終ファイルを生成

### フロントエンド側の流れ

```
1. 大きなファイルをチャンクに分割
2. 各チャンクを index 付きで upload_file_chunk に POST
3. 全チャンク完了後、concat_uploaded_file_chunk で結合を要求
4. 結合後のファイルパスを受け取り、モデルインポート等に使用
```

## 採用理由

- **リクエストサイズ制限の回避**: ブラウザ・サーバー双方の制限を超えるファイルを扱える
- **進捗表示**: フロントエンドでチャンク単位の進捗を表示できる
- **メモリ効率**: 大きなファイルを一度にメモリに載せない
- **v1 互換性**: フロントエンドが既にこのプロトコルに合わせて実装されている

## 既知の懸念点

- **同時アップロード時の競合**: 同一ファイル名で同時にアップロードすると競合する可能性がある (v1 でも未対応)
- **失敗時のクリーンアップ**: アップロード途中で失敗した場合、チャンクファイルが `upload_dir` に残り続ける (v1 でも未対応)
- **認証・認可なし**: アップロードエンドポイントに認証がない (ローカル利用前提のため現状は許容)

## 将来の改善案

- アップロードセッション ID を導入し、同時アップロードの競合を防止
- TTL 付きのクリーンアップ処理で孤立チャンクを定期削除
